# Milestone 10 — administrator AI assistant and read-only MCP

Owner: Bernie. Original direction: 2026-10-13, ADR 0038. Model-first Gemini/Claude expansion approved 2026-10-15, ADR 0039. Multisite, cloud monitoring and automated repairs remain deferred.

## Dependent implementation slices

1. Contracts/settings: native administrator-only access, independently encrypted provider credentials/consent, separate MCP opt-in and revision-guarded serialized settings writes.
2. Evidence projection: shared allowlisted plugin help/configuration/diagnostics/health/activity. Timestamp, revision and freshness accompany each question. Observed facts are generated by the server; model causes/steps remain advisory.
3. AI adapters: OpenAI Responses, Gemini GenerateContent and Claude Messages, fixed official origins and credential headers, shared structured answer validation, no remote tools/redirects and bounded requests. OpenAI and Gemini use `store:false`; provider-specific retention terms still apply.
4. Private chat: encrypted site/owner-bound history and titles, rename/delete, bounded sidebar reads, 100 messages/session, 4,000 characters/input, thirty-day inactivity expiry and atomic per-conversation claims.
5. Confirmed diagnostics: administrator/nonce/revision guards remain in the backend, but the Chats panel does not currently offer a diagnostic-run control. Administrators use the Diagnostics page for current findings. No mail, configuration changes, retries or failover tools.
6. MCP: separately enabled, HTTPS Application Password authentication, native administrator/Origin checks, negotiated 2025-06-18 or 2025-03-26 protocol and five fixed read-only tools.
7. Security/lifecycle QA: additive schema 0.14.0, bounded counters/cleanup, default retention, explicit uninstall deletion, mock adversarial tests, disposable SQL and sampled local UI checks.

All slices are implemented in the feature snapshot. Local validation is not live model acceptance, verified external-client compatibility or release certification. See the dated QA record for results and outstanding gates.

## Setup after review

1. Open AI Assistant → Settings. Confirm server encryption is available.
2. Choose a starter model from the grouped selector. Its provider settings appear below. Candidate models are visible before setup, not a promise of account access. OpenAI retains its existing four models; Gemini offers `gemini-3.5-flash-lite` and `gemini-3.8-flash`; Claude offers `claude-haiku-5-5` and `claude-sonnet-5-5`. No default, automatic model upgrade or vendor fallback is selected.
3. Enter that provider’s API key privately, leave chat disabled and save. Verify the saved key/model access. This checks the bounded account-visible model list, not paid inference quota. If the selected model is absent, chat remains unavailable.
4. Review that provider’s data-sharing/billing notice, explicitly consent, enable chat and save. Replacing/removing a key invalidates that profile’s verified models and disables chat; the candidate selection remains visible for re-verification. Other providers’ encrypted keys and consent are kept separately. A provider change requires a new chat before any old conversation is transmitted. Each new assistant message records provider/model provenance. The chat list and open conversation show the recorded provider; an empty chat shows the currently selected provider with a “selected” qualifier until its first answer binds it.
5. Ask a plugin-related question in Chats. New chats receive a concise title locally from their first saved, redacted question, without an additional AI request. Existing chats retain their names, and manual renames are never replaced automatically. Rename opens an in-page title form; delete opens a separate irreversible-action confirmation. Cancel or Escape leaves the chat unchanged. Generic unrelated questions are locally declined; model refusals and response/citation validation add further safeguards. Short contextual follow-ups are supported, but topic filtering is conservative and not a perfect semantic boundary.

OpenAI may retain data under its own account/platform policies despite `store:false`. No recipients, subjects, bodies, raw headers, keys, raw diagnostic text or provider response bodies are attached as evidence. Recognizable credentials/raw header inputs are blocked and addresses are removed from free text; detection cannot guarantee that users never type other sensitive content.

Gemini unpaid-service data may be used to improve Google products; availability, limits and terms depend on model/account. Claude requires Anthropic API credentials, not a Claude chat login. Anthropic displays the full key only at creation; the existing-key list contains a shortened hint that cannot authenticate. Use a securely saved full secret or create a new key, then save it before checking model access. No vendor is promised to be free or to provide zero retention. The starter catalogue must be maintained against official lifecycle/API documentation; only account-visible supported entries are verified. Gemini/Claude models are read from one bounded page (maximum 1,000 entries); the plugin does not follow arbitrary pagination URLs, and an absent entry is not enabled.

Version-2 AI options normalize the earlier OpenAI profile without writes on reads or changing existing ciphertext/context. Explicit saves persist isolated profiles. No database schema bump is required. Before downgrading to the earlier single-provider implementation, disable AI and retain/restore the backed-up AI option; old code cannot interpret the new profile layout. Conversation tables, expiry and MCP rules are unchanged.

## MCP connection

Enable MCP separately after reviewing the warning. Configure a compatible client for the displayed `/wp-json/scalyn-mail-relay/v1/ai/mcp` HTTPS endpoint with administrator Application Password HTTP Basic authentication in the Authorization header. Enter/store the password in the trusted client, never in a URL or plugin settings. Revoke it from the WordPress user profile when unused.

Application Passwords retain broader WordPress account permissions. This is not an OAuth authorization server or a promised ChatGPT connector. MCP supports stateless Streamable HTTP JSON responses, not GET/SSE subscriptions. Send Content-Type application/json and Accept application/json, text/event-stream; negotiate a supported protocol and send MCP-Protocol-Version on subsequent requests.

Tools: `plugin_help`, `configuration_summary`, `recorded_diagnostics`, `health_explanation`, `aggregate_activity`. Each takes an empty arguments object and returns bounded redacted evidence. There is no chat-history, diagnostic-run, setting-write, sending or retry tool. External AI conversation topics are outside the plugin server's control.

## Operations and rollback

Limits: five inference attempts per administrator/minute, 100 per site/UTC day, 1,200 output tokens/reply, one live claim per conversation. Failed network attempts consume budgets; there are no automatic billable retries. MCP has a separate sixty-request administrator/minute budget. New chats are limited to ten per administrator/minute. The sidebar shows twenty most recently active conversations; reads remain bounded. Earlier conversation context and declined turns are omitted from model history when necessary, with a visible context-omission notice.

Expiry is enforced on reads and by existing scheduled cleanup even with AI disabled. Deactivation clears owned scheduled hooks. Uninstall retains AI settings/history unless the existing explicit deletion policy is selected. Missing/rotated encryption keys make encrypted content unavailable; no plaintext fallback is allowed.

Disabling access stops new requests; a request already dispatched to an external service cannot be recalled. Settings use the existing scoped option-lock pattern; an interrupted save can require administrator repair of a stranded write lock. No remote API request is made while holding that lock.

Before deploying, back up plugin and database. A code rollback leaves additive AI tables and encrypted data in place; it does not reverse migrations. Disable AI/MCP before downgrading. Normal mail sending does not depend on the AI provider, key, model or consent.

Remaining acceptance gates: owner UI review, private key/model configuration, consented live model/topic/redaction evaluation, and approved public HTTPS MCP testing with a real compatible client. No production deployment or automatic merge.
